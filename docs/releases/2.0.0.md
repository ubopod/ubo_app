# Ubo App 2.0

Version 2.0 is the largest architectural shift in the project's history. The core
was **split from its UI**: it now runs headless, computes everything it wants
drawn as serializable view data, and streams that to **interchangeable thin
clients** over gRPC. On top of that foundation, the voice assistant grew into a
multi-provider AI platform and the Docker app catalog gained serious remote-access
tooling.

These notes cover the development branch changes after `v1.7.0` through HEAD.

> **Heads-up:** 2.0 is a **breaking** release. The GUI is now a separate gRPC
> client installed in its own virtualenv, and the in-state menu/callback model
> was replaced by dynamic menus + an action registry. See **Upgrade notes** at
> the bottom.

## Headline: headless core + thin-client architecture

The monolithic Kivy app is gone. In its place:

- **A headless core** that owns all state and logic, with no direct display, SPI,
  or `ubo-gui` dependency.
- **View computation in the reducer** — the core derives typed, fully-serializable
  `ViewData` (menus, notifications, applications, home/status bar) from state and
  ships it over gRPC. No widgets or callables cross the wire.
- **Redux-based navigation stack** — navigation is now a `stack` in state with
  menu/application/notification items; `path` is reactive and derived. The legacy
  static menu tree and `SetMenuPathAction` were removed in favor of **dynamic
  menus** registered by services.
- **An action registry** — menu items carry string `action_id`s resolved to
  handlers, replacing in-state callbacks. This is what makes remote rendering
  possible.

Three clients now consume that stream:

- **Kivy GUI client** — a standalone gRPC client (its own venv) replacing the
  in-process GUI, with transition animations, viewfinder streaming, image viewer,
  and screenshot-over-gRPC.
- **Textual TUI** — a brand-new terminal thin client with full menu navigation,
  notifications, headings, input forms, file upload/download flows, QR/render
  views, and progress visibility.
- **Web UI** — rebuilt on a React component architecture with a page registry,
  chat, QR pages, volume control, mic streaming, file flows, and camera
  viewfinder. The Web UI has a tile-based design navigable by keyboard keys.

This split drove a wide refactor toward **pure reducers, immutable/serializable
state, and registry-based menu/path/data providers** — the groundwork everything
else builds on.

## Assistant: a multi-provider AI platform

The assistant was upgraded to the **Pipecat 1.0 → 1.3 API** and expanded
dramatically:

External clients can now drive the assistant through the gRPC store API, not
only through the built-in voice/chat surfaces. Clients may dispatch one-shot
transcribe, complete, synthesize, or generic `AssistantRunPipelineAction`
requests for contiguous STT → LLM → TTS pipeline chains, choose providers and
models per request, and receive streamed text, audio, image, error, and final
frames back through assistant report events keyed by `session_id`. The same API
also exposes live conversation control for external clients: start, stop,
toggle, stop-talking, and remote mic sessions identified by `audio_source`.

- **Many new LLM providers** — Anthropic, Qwen, DeepSeek, OpenRouter, Mistral,
  Grok, Venice AI, Cerebras, plus **multiple named generic OpenAI-compatible
  providers** and auto-registered **Hermes**. Per-provider model pickers and
  credential confirmation flows.
- **On-device & offline** — Ollama on-device catalog with RAM gating and a
  thinking toggle; **Kokoro offline TTS**; user-selectable **Vosk** STT model per
  system language; a multi-voice **Piper** catalog with per-voice download
  lifecycle.
- **Conversation UX** — conversation mode, barge-in, stop-talking phrase,
  per-trigger source metadata with policy-driven turn-ending (silence timeout +
  end-of-turn phrases), and a 5-second mic buffer dump on wake.
- **Chat widget** wired into both the GUI client and Web UI, backed by the live
  Pipecat pipeline with a parametrized run-pipeline action/event.
- **MCP** gained typed server configurations over gRPC and a lifecycle fix for
  Pipecat 1.0.
- **Image generation** now defaults OpenAI requests to `gpt-image-1` and handles
  both URL and base64 image responses.
- Credentials are now driven by the secrets file as the single source of truth,
  with live key refresh for cloud STT/TTS services.
- Assistant diagnostics improved with STT transcript logging, assistant service
  logs on disk, provider-error notifications from the live pipeline, and
  optional Pipecat Whisker debugging.

## Docker: remote-access apps & data durability

- **LAN exposure toggle** per Docker app, categorized **app nesting/navigation**,
  and remove/delete sorted last.
- New apps and compositions — **Pangolin** site runner, **Twingate**, **n8n**,
  **OpenClaw**, and a **Hermes** composition, with Hermes data **decoupled from
  the image via host bind mounts** so it survives reinstall.
- **OpenClaw** gained a richer setup flow for model providers, API keys, channel
  providers, pairing, gateway tokens, and LAN-exposure safety configuration.
- The app catalog moved to per-app modules with startup port monitoring and an
  **Envoy** frontend path for grpc-web.

## Media, filesystem, infrared, voice & audio

- **Filesystem over Web UI** — file/directory **download**, chunked **upload via
  gRPC**, and audio/video playback in both GUI and Web UI; hardened previews
  (large images downscaled rather than refused).
- **Gapless audio streaming** with global playback interruption, a stop-playback
  action/event, a boot-ready chime, and clean shutdown of the playback thread.
- **Camera** — client-selectable source with viewfinder frames streamed to the
  GUI client over gRPC.
- **Infrared** — users can register and replay IR keys from the UI, and the Web
  UI can assign registered keys to bindable actions such as assistant controls,
  menu actions, and custom service actions. New instruction/prompt stack
  rendering is shared by the GUI and Web UI.
- **Voice commands** — users can create short custom voice commands from the Web
  UI, map them to the same bindable-action registry used by infrared, and use a
  regex-style compact phrase-pattern syntax for optional words and alternatives.
  Defaults cover assistant controls, menu navigation, lights, volume, WiFi flows,
  and IR receive; intent listening now times out cleanly after 10 seconds.

## New services

- **Localization** service for system language.
- **System-metrics** service reporting CPU/RAM/storage, surfaced on the home view.

## gRPC & performance

- **Multiplexed event subscriptions** to work around the HTTP/1.1 connection
  limit; **grpc-web routed through an Envoy frontend**.
- Audio mic dispatches made cancelable so they **stop starving control actions**.
- Serialization optimized with caching and BasicType flattening; **view-computation
  dispatches cut ~62%** via startup gating, split autoruns, and lazy registration.
- Animated splash screen and faster GUI startup.

## Important bug fixes

- **Assistant and audio** — fixed listening key-repeat behavior, constrained each
  listening session to one audio source, flushed trailing silence on push-to-talk
  release so streaming STT finalizes, improved end-phrase matching, rebuilt the
  active Ollama service after model downloads, and added Ollama container-status
  and model-download fallback handling. Vosk now lazy-loads selected models so a
  missing or still-downloading model no longer kills the STT slot, Qwen accepts
  DashScope `sk-ws-` keys, and camera/image capture for vision prompts avoids
  duplicate descriptions.
- **Capture and playback** — released the exclusive ALSA capture device on close,
  increased the input capture period to reduce capture pressure, fixed audio
  clicking artifacts and video playback speed, stopped browser mic dispatch from
  starving control actions, and hardened browser mic handling against resource
  exhaustion and insecure contexts.
- **Notifications and navigation** — notification dismissal now targets the
  visible item, generic stack pops clear notification state, stack push/pop is
  ordered in the reducer, background notifications are filtered out of active
  views, dynamic notification actions are re-bound after reloads, and duplicate
  stack pushes are prevented.
- **GUI, Web UI, and chat** — latest-wins transition queues prevent stale view
  animations, prompt views update in place, the desktop GUI window is restored
  reliably, image viewer zoom/scroll works from the physical keypad, Web UI
  status/breadcrumb bars stay fixed, mobile tile grids truncate safely, Web UI
  text inputs submit through Flask instead of gRPC, render-view prop updates
  replace stale props on kind changes, keypad up/down continues to pan and zoom
  render/application views, and chat overlay/bubble layout was stabilized.
- **Filesystem, Docker, and remote access** — fixed upload race conditions and
  HTTP upload routing, avoided forcing selector depth to zero, prevented Docker
  event monitors from starving fetch workers, matched container events by
  registry-stripped image paths, isolated event-monitor bootstrap, rewrote
  compose port bindings correctly for loopback/LAN modes, and stopped VS Code
  status-flow crashes from spamming on-screen errors.
- **Device, OTA, and test infrastructure** — released keypad/display GPIO pins on
  cleanup, prevented Kivy logger recursion, ran screenshot handling on the Kivy
  main thread, installed the GUI client in an isolated venv during OTA/deploy,
  pinned internal packages to the target update version, restarted the app only
  after all wheels are installed, ignored orphaned `~`-prefixed service
  directories, mirrored the test-runner workspace before device tests, and
  hardened Pi 4/5 snapshot synchronization.

## Upgrade notes

- 2.0 is a **breaking** release. The GUI is now a separate gRPC client installed
  in its own virtualenv — OTA updates and deploy scripts now install that client
  separately and pin internal packages to the target update version.
- Any external integration that relied on in-state callables or the old
  menu-tree / `SetMenuPathAction` must migrate to the **dynamic-menu +
  action-registry** model.
